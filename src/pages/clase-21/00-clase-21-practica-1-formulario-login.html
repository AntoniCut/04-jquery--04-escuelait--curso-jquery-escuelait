Práctica 1: "Sistema de login con experiencia de usuario enriquecida"

Curso de jQuery EscuelaIT

Objetivo: Se trata de hacer un completo sistema de login de usuario, aunque limitando el desarrollo a lo que sería la parte Front-end. El sistema tiene que ser dinámico y sencillo de usar, además de responder ante posibles errores de una manera amigable.

Esquema de funcionamiento

Basamos este trabajo en varias partes, que enumero en "orden de aparición".

  1. En la página habrá un enlace para "Login de usuario"
  2. Al pulsar ese enlace se mostrará un formulario de login en una "caja dinámica". El tipo de caja será en función de vuestra creatividad. Podéis intentar hacer lo que llaman una "caja modal" o cualquier otra solución que tenga al menos un efectillo para darle gracia. Como sugerencia, podéis hacer una capa flotante, posicionada de manera absoluta con CSS y que la caja aparezca por un lado y se posicione en el centro de la página con un movimiento suavizado. Otra opción quizás más simple es que se posicione en el centro de la página y aparezca con un fundido de transparente a opaco. Aquí teneis libertad para intentar e inventar lo que se desee.
  3. En la caja de login habrá un formulario con 2 campos, usuario y clave (aparte del botón de submit para enviar el formulario)
  4. Al submitir el formulario se enviarán los datos por Ajax, usando POST al servidor.
  5. No necesitamos hacer la parte de programación del lado del servidor para autenticar al usuario, simplemente se nos devolverá un JSON literal que tendremos almacenado en un archivo de texto plano.
  6. El JSON que recibirás contiene varios datos, pero básicamente nos debe decir si la supuesta validación ha sido positiva o negativa. El JSON tendría una forma como esta

    En caso de ser válido el usuario: 

    {
    "valido": true,
    "mensaje": "Entrando..."
}

    En caso de NO ser válido el usuario: 

    {
    "valido": false,
    "mensaje": "No se corresponde el usuario o la clave"
}
  7. Una vez recibida la respuesta JSON:
    1. Si el login NO es válido, entonces aparece el "mensaje" de fallo en rojo en un sitio cercano al formulario de login, el usuario podría entonces revisar los datos que ha escrito para hacer login y volver a enviar el formulario.
    2. Si el login era válido, entonces muestra en verde el "mensaje" recibido en el JSON y al cabo de 2 segundos se oculta la capa de login.
